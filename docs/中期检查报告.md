## 一、已取得成果

### 1.1 开源代码

项目代码已在 GitHub 开源（`https://github.com/1hzl/low-precision-fft`），包含 57 个文件、约 13,000 行代码，覆盖 GPU CUDA 内核、PyTorch C++ 扩展封装、Python 算法原型和自动化测试体系。外部 API 简洁统一：

```python
import lowp_fft
X = lowp_fft.fft(x, precision="fp16")   # cuFFT FP16 加速
X = lowp_fft.fft(x, precision="bf16")   # cuFFT BF16 加速
X = lowp_fft.fft(x, precision="fp8")    # 自研 BFP FP8
```

### 1.2 独立可复现性验证

完成了跨平台独立验证，覆盖 7 台独立机器、8 位验证者、4 代 NVIDIA GPU 架构：

| GPU | 架构 | SM | Passed | E4M3 SQNR |
|-----|------|----|--------|-----------|
| RTX 5070 Ti Laptop | Blackwell | sm_120 | 94 | 21.17±0.16 dB |
| RTX 4060 Laptop | Ada | sm_89 | 94 | 21.17±0.16 dB |
| RTX 5060 Laptop | Blackwell | sm_120 | 94 | 21.17±0.16 dB |
| RTX 5090 | Blackwell | sm_120 | 94 | 21.15±0.15 dB |
| RTX 4090 | Ada | sm_89 | 94 | 21.15±0.15 dB |
| RTX 3090 | Ampere | sm_86 | 94 | 21.15±0.15 dB |
| Tesla V100S | Volta | sm_70 | 54¹ | 21.15±0.15 dB |

> ¹ V100 的 41 个 BF16 测试失败为硬件设计预期（Volta 无 BF16 Tensor Core），项目 API 层已实现自动检测降级。

**核心结论**：非 Volta 6 台机器 94/94 核心测试零差异通过；E4M3 SQNR 跨 7 台机极差仅 0.02 dB（21.15–21.17 dB），远小于统计误差（±0.15 dB），证明 BFP FP8 精度完全由软件定义、与 GPU 架构无关。

### 1.3 自研 BFP FP8 算法

设计并实现了块浮点（Block Floating-Point, BFP）FP8 FFT 算法，核心创新为"每阶段共享指数 + 蝶形 float32 全精度计算"：

- 相比 naive FP8（逐算子量化，SQNR ~0 dB），BFP 达到 ~21 dB（提升 20+ dB）
- 每元素仅 2 bytes 存储（vs FP16 的 4 bytes），适合内存受限的边缘部署场景
- 同时实现 Python 原型和 CUDA kernel（846 行）

### 1.4 技术文档

产出技术文档 6 份：独立验证报告、验证指南（VERIFY.md，用于指导第三方验证者）、FP8 误差模型、FP8 策略对比分析、Sprint 3.4 终期报告、Bergach 2026 论文复现报告。

### 1.5 论文/专利/竞赛

暂无。项目当前处于算法研发与工程实现阶段，后续计划在 LLM 微调场景验证完成后整理成果投稿。

### 2.2 已完成工作详述

**Phase 1 — CUDA 环境验证**：cuFFT FP16 hello world 在 RTX 5070 Ti 上验证通过，确认开发环境可用。

**Phase 2 — FP16/BF16 cuFFT 集成 PyTorch**：基于 cuFFT Xt API（`cufftXtExec` + `CUDA_C_16F/BF`）实现 C++ 扩展，支持自动微分（`torch.autograd.Function`），PlanCache 线程安全（double-checked locking, 64 条目）。支持 `n` / `dim` / `norm` 参数，fallback 时自动警告。

**Phase 3 — FP8 BFP 全链路**：完成论文分析 → 误差建模 → Python 原型（22 tests passed）→ CUDA kernel v0（846 行，含 bit-reverse、per-stage DIT、requantize、dequant）→ 调优报告。完成 Bergach 2026 论文 SQNR 数据复现。

**Phase 4 — BFP 功能补全与质量收尾**：实现 inverse FFT、CPU fallback、bandwidth 测试。完成两轮代码审查（4 MAJOR + 3 MINOR 修复）。测试从 31 扩展到 114，非 Volta 机器 94/114 稳定通过。

**独立验证**：组织 8 位验证者（含 2 位外部邀请 + 4 台 AutoDL 云电脑），覆盖 6 种 GPU 型号、CUDA 12.8–13.3.33、PyTorch 2.8–2.11、Win 11 + Linux。全部验证日志归档于项目仓库 `verification-logs/`。

## 四、项目存在问题及解决方案

### 4.1 主要问题

| # | 问题 | 严重程度 | 影响 |
|---|------|:--------:|------|
| 1 | CPU SIMD 多架构适配（x86 AVX2/ARM NEON/RISC-V）尚未启动 | 🔴 高 | 任务书核心要求，当前完全空白 |
| 2 | LLM 微调场景验证未开展 | 🟡 中 | 应用价值无法证明，影响答辩和论文 |
| 3 | BFP FP8 CUDA kernel 性能待优化（当前 ~0.01× FP16） | 🟡 中 | Python↔CUDA 多次拷贝是瓶颈 |
| 4 | PyTorch 社区贡献流程（Contribution Guide/PR/CI/CD）未研究 | 🟢 低 | 项目终极目标的前置条件 |
| 5 | 多架构 CPU 测试环境未搭建 | 🟡 中 | ARM/RISC-V 交叉编译需要额外硬件 |

### 4.2 解决方案

**问题 1（CPU SIMD）**：Phase 5 启动。优先 x86 AVX2（开发环境已有），其次 ARM NEON（需租赁 ARM 云实例进行交叉编译验证）。利用编译时宏定义实现指令集自动检测与适配，参考 ARM ACLE 规范和 Intel Intrinsics Guide。

**问题 2（LLM 验证）**：Phase 6 启动。基于 BCA 论文（arXiv 2505.00582）中 FFT 用于 LLM 微调的具体路径，构建包含典型序列长度和 batch 规模的测试集，对比低精度 FFT 与原生 FFT 在精度（梯度收敛性）和性能（吞吐量、显存占用）上的差异。

**问题 3（BFP 性能）**：融合量化-蝶形-重量化 kernel，消除多次 Python↔CUDA 边界跨越和中间结果的显存读写。

**问题 4（社区流程）**：Phase 7 研读 PyTorch Contribution Guide，参考社区已合并的低精度算子 PR（如 FP8 相关 PR），制定提交策略。

**问题 5（多架构环境）**：使用经费余额租赁 ARM 云实例，配合 QEMU 用户态模拟进行本地预验证。
