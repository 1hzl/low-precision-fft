# arXiv:2605.28451 — Bergach (2026-05-27)

## "Range, Not Precision: Block-Floating-Point Half-Precision FFT and SAR Imaging on Apple Silicon"

**作者**: Mohamed Amine Bergach
**平台**: Apple M1 (fanless MacBook Air)
**相关性**: ⭐⭐⭐⭐⭐ 直接命中 Phase 3 方案

---

## 核心论点

**传统观点错了**：FP16 FFT 的限制不是尾数精度（10-bit mantissa），而是指数动态范围（5-bit exponent）。

- FP16 mantissa → ~42 dB 理论 SQNR
- 实测 FP16 FFT mantissa-limited at **56-61 dB SQNR** — 雷达可用！
- 但 naive FP16 SAR pipeline 产生纯 NaN：因为 conjugate-FFT-conjugate IFFT 使幅值增长 O(N²)

## 解决方案：固定偏移 BFP

- 每次 IFFT 前乘以 1/N，中间值限幅 < 4096
- 级联效果：range-compression output → O(1) 而非 O(N)
- **改动仅两行 kernel 代码**

## 结果

| 指标 | 值 |
|---|---|
| FP16 FFT throughput | **306 GFLOPS** (radix-8, N=4096) |
| FP32 baseline | 139 GFLOPS |
| 加速比 | **2.2×** |
| SAR 质量 | PSLR/ISLR/SNR/resolution 匹配 FP32，误差 < 0.1 dB |
| 端到端 SQNR | 42 dB |

## FP8 结论 ⚠️

> "FP8 (E4M3/E5M2) collapses to **14–20 dB SQNR**, making FP16 today's precision floor for FFT-based radar"

FP8 的 SQNR 崩塌到 14-20 dB — 远低于可用水平。
FP16 是 FFT 的精度下限，FP8 需要未来的精度恢复方法才能突破。

**对我们的影响**：
- FP8 E4M3 有 3 位尾数，而 FP16 有 10 位尾数 → 差距巨大
- 块浮点解决了指数溢出问题，但无法挽救尾数不足
- Phase 3 FP8 目标应从"实用 FFT"调整为"研究性探索"
- FP8 的 killer app 可能在 SAR/雷达之外（如频域神经网络的容忍度更高）

## 关键引用

- tcFFT: Tensor Core FFT, 1.29-3.24× over cuFFT FP16, ~35 dB
- Hunhold & Gustafson: FP16 overflow in FFT spectral methods, 推荐 bfloat16/posit/takum
- 块浮点方案仅需 2 行 kernel 代码改动 = single 1/N shift schedule

## 对 Phase 3 的影响

1. **方案确认**：块浮点（BFP）是正确的，论文验证了可行性
2. **复杂度大降**：fixed-shift schedule 仅需 1/N 缩放，不需要复杂的分层动态缩放
3. **FP8 预期调整**：14-20 dB SQNR 意味着目标应设为研究探索性，而非实用
4. **可直接复用**：论文的 fixed-shift BFP 策略可以直接移植到 CUDA
