# 科研项目审查指南

> low-precision-fft 专用。当 auto-review 触发时参考本文标准。

## 审查维度（科研扩展）

除标准审查维度（正确性/架构/安全/可读性）外，科研项目增加：

### 🧪 实验设计
- 实验目标是否明确？假设是否可证伪？
- 对照组设置是否合理？
- 指标是否客观可量化？
- 单次实验结果不应作为结论（需复现或误差范围）

### 📚 文献引用
- 是否有相关论文支撑技术选型？
- 引用是否标注 arXiv ID 或 DOI？
- "我们找不到相关文献" 不是充分论据——要写"在 <范围> 内未检索到"

### 🔬 算法正确性
- 涉及数值计算的改动必须带精度验证
- FFT 变换需验证 Parseval 定理（时频域能量守恒）
- 新增 kernel 需通过 `ctest` 或等价基准

### 📊 数据管理
- 基准测试数据保存到 `data/` 目录
- 命名格式：`{日期}-{精度}-{尺寸}-{描述}.json`
- 不得提交大型二进制数据文件（>1MB）

## 审查宽松度

| 项目阶段 | 审查力度 |
|----------|---------|
| Phase 1（环境验证） | 宽松：只检查硬约束 |
| Phase 2-3（核心开发） | 严格：全维度审查 |
| Phase 4-5（收尾） | 标准：通过即可 |

## 不建议阻塞的情况

- 实验性代码标注了 `[wip]` 或 `[experimental]`
- 注释中明确写了 "TODO: 需进一步验证"
- 基准数据缺失但 commit message 说明了原因
